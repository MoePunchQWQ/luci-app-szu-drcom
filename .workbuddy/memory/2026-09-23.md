# 2026-09-23

## 创建 luci-app-szu-drcom 插件

面向深圳大学的 OpenWrt LuCI Dr.COM 校园网认证插件，参考了两个仓库：

- `BH4ME/szu_drcom` — 深大是 **Dr.COM ePortal（HTTP Portal）** 协议，不是 dogcom UDP。
  登录 `http://<portal>:801/eportal/portal/login?callback=drlogin&login_method=1&user_account=..&user_password=..&wlan_user_ip=..&wlan_user_mac=..&wlan_ac_ip=..&terminal_type=2&jsVersion=4.X`
  状态 `http://<portal>/drcom/chkstatus?callback=drstatus&jsVersion=4.X`
  下线 `/eportal/portal/logout`
  默认 portal=172.30.255.42, port=801, ac_ip=172.30.255.41
- `sweetcornna/jlu_drcom` — 只借鉴 LuCI 工程结构（controller + view + procd init.d + Makefile）；
  其 dogcom C 代码（UDP 61440）不适用于深大。

### 产出

- `files/usr/bin/szu-drcom`：ash 客户端，子命令 status/login/logout/daemon/probe
- `files/etc/init.d/drcom_szu`：procd 服务
- `files/etc/config/drcom_szu`：UCI 配置
- `files/usr/lib/lua/luci/controller/szu_drcom.lua` + `view/szu_drcom/status.htm`：LuCI 面板
- `Makefile`（包名 luci-app-szu-drcom）、`README.md`、`LICENSE`

### 踩过的坑（重要）

1. **Portal 响应含 GBK 中文（非法 UTF-8 字节）**，UTF-8 locale 下 sed/grep 的 `.` 和 `[^"]`
   会失配，导致 IP 提取出垃圾串。解决：脚本头部 `export LC_ALL=C` 强制按字节处理。
2. **`tr -d ':-. '` 报 reverse collating order**——GNU tr 把 `:-.` 解析成反向区间。
   改用 `tr -cd '0-9A-Fa-f'`（取补集）后 `tr 'a-f' 'A-F'`。
3. IP 提取正则值部分必须用 `[0-9.]*` 而非 `[^"]*`，并加 `grep -E '^[\d.]{7,15}$'` 兜底。
4. LuCI 复选框未勾选时不提交字段，UCI 保存需显式写 `"0"`，否则无法取消。
5. 本 Bash 沙箱用 safe-bin shim 拦截命令，`env PATH=...` 注入假二进制**无效**；
   改用「在 wrapper 脚本里定义同名 shell 函数 + source 目标脚本」的方式做冒烟测试。

### 验证

开发机本身就在 Dr.COM 网络内，真实 Portal 可直连：`szu-drcom status` → online，
IP 172.29.40.121；`probe` 能读出 AC 标识。前端页面无法在本机渲染，仅做了
Lua 解析 + 模板标签配对校验，未在真实 LuCI 上验证。

## 追加：菜单不显示（用户反馈已装上但 LuCI 无「服务」入口）

根因定位（读了 LuCI master 源码确认，非猜测）：
- `modules/luci-base/ucode/dispatcher.uc` 的 `build_pagetree()` 同时 glob
  `/usr/share/luci/menu.d/*.json` 和 `/usr/lib/lua/luci/controller/*.lua`
- 对 `.lua` 走 `load_luabridge(true)`，即 `require('lua')`；**失败时只打一条 warn
  「Lua controller ... present but no Lua runtime installed.」然后跳过**，
  界面完全无提示 → 表现就是菜单项静默消失
- 所以 **缺 `luci-lua-runtime` 是首要原因**
- 另：`dependent` 不在 ucode 版 schema 里（schema 只有 action/auth/cors/css/depends/
  order/setgroup/setuser/title/wildcard/firstchild_ineligible），会被忽略；
  旧版 LuCI 里反而可能隐藏无子节点。已从控制器移除该设置。
- `node.satisfied = check_depends(spec)`，只有显式设 `depends` 才会隐藏，我们没设
- 索引缓存 `/tmp/luci-indexcache.<hash>.json` 按 ino/mtime/size hash 文件列表，
  新增 controller 会自动失效，但清 `/tmp/luci-indexcache*` 仍是最省事的兜底

排障命令已写进 README「菜单不显示」专节。Lua 版本（5.1 vs 5.4）与
`module()` 兼容性尚未排除，待用户反馈 logread 原文。

## 追加：新增 scripts/build-apk.sh（面向 GitHub 发布）

产出 `dist/luci-app-szu-drcom-1.0.0-r2.apk`，默认 apk v2 容器，`--v3` 走 `apk mkpkg`。

### apk v2 格式的三个硬约束（全部实测确认，踩过坑）
1. **datahash = 数据段 gzip 原始字节的 sha256**，不是解压后 tar 的 sha256。
   用真实 Alpine 包（grub-2.12-r7）拆 3 个 gzip 成员验证：只有 member#2 的
   raw 字节 sha256 与 .PKGINFO 里的 datahash 匹配（解压后的不匹配）。
2. **控制段不能有 tar 结束标记**（末尾 1024 全零块），否则 apk 解析到那里就停，
   永远读不到数据段。abuild 用 `abuild-tar --cut`，脚本里用 dd+cmp 反向扫描
   全零块再截断实现。数据段反而**必须**保留结束标记。
   验证：真实包控制段 7680 字节、末尾 1024 非全零；数据段末尾 1024 全零。
3. **apk-tools 3.x 强制要求每个文件带 `APK-TOOLS.checksum.SHA1` pax 扩展头**，
   否则报 `file format is obsolete (e.g. missing embedded checksum)`，一个文件
   都装不上（2.14.6 只是 warning，3.0.8 直接 ERROR）。试过 `--force-old-apk`
   等开关无效。
   → **GNU tar 写不了每文件 pax 关键字**：`--pax-option=KEY=VALUE` 对未知关键字
   只会写进"全局头"（typeflag 'g'，名字 `/tmp/GlobalHead.1`），apk 完全忽略；
   `KEY:=VALUE` 则什么都不写。已知关键字（如 comment）同样进全局头。
   → 解决办法：**有 python3 时用 python 的 tarfile（PAX_FORMAT + ti.pax_headers）
   生成数据段**；没有则退化成不带校验和的包并告警（只能装 apk-tools 2.x）。

### 验证方式（可复用）
下载 Alpine 静态 apk 工具即可在本机真装包，无需 root：
- apk-tools 2.14.6: v3.21/main/x86_64/apk-tools-static-2.14.6-r3.apk
- apk-tools 3.0.8: v3.23/main/x86_64/apk-tools-static-3.0.8-r0.apk
版本号从对应 repo 的 APKINDEX.tar.gz 里 grep `^P:apk-tools-static$` 取。
装包：`apk.static add --usermode --allow-untrusted --force-non-repository
--initdb --no-network --root <dir> <pkg.apk>`（apk3 非 root 必须 --usermode）。
注：非 root 下 .post-install 会报 chroot/execve 失败，属环境限制，非包缺陷。

### 其他踩坑
- 控制段文件名要裸存 `.PKGINFO`，不能是 `./.PKGINFO`（apk 按名精确匹配）
- 数据段别既列目录又列文件，GNU tar 会把重复项转成硬链接条目（typeflag '1'）
- `set -u` 下 `: "${VAR-默认}"` 只展开不赋值，必须写 `VAR="${VAR-默认}"`
- 未验证：真实路由器上的 `--v3` 安装、非 root 外脚本执行
